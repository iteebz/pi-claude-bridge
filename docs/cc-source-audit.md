# CC Source Audit — Bridge Assumptions vs Reality

Audited 2026-08-26 against CC 2.0.89 source. For how CC's pipeline works,
see `docs/cc-internals.md`. This doc is verdicts only.

## Seam 1: JSONL fields — ✅ Correct

Every field the bridge writes is either load-bearing and correct, or inert.

| Field | Verdict | Notes |
|-------|---------|-------|
| `uuid` | ✅ | Deterministic UUIDs stabilize [id:] tags across rebuilds |
| `parentUuid` | ✅ | Linear chain matches CC's walk |
| `timestamp` | ✅ | Monotonic, no ties → deterministic sort |
| `isSidechain` | ✅ | `false` for main conversation |
| `message.id` | ✅ | Unique per assistant → no unintended merging |
| `isMeta` | ✅ | Omitted (= not meta) → correct for real user turns |
| `cwd` | ✅ | Normalized to match CC's runtime |
| `userType` | ✅ | Inert — never read by normalization |
| `requestId` | ✅ | Inert |
| `slug` | ✅ | Inert — CC overwrites on next write |
| `entrypoint` | ✅ | Analytics only |
| `version` | ⚠️ | Hardcoded `"2.1.83"` — no impact today, could gate future compat |
| `gitBranch` | ⚠️ | Hardcoded `"HEAD"` — no impact today |

## Seam 2: Tool pairing — ✅ No double-repair

Bridge repairs before writing (synthetic `is_error` results). CC repairs after
normalizing (`ensureToolResultPairing`). Compatible and idempotent — CC sees
bridge's synthetic results as validly paired → skips. CC's additional dedup
(duplicate IDs, server_tool_use orphans) can never fire on bridge output.

## Seam 3: Attachments — ✅ Placement correct

Bridge places `@file` after parent user record. CC's `reorderAttachmentsForAPI`
bubbles to nearest stopping point — compatible with bridge placement. Only
`type: "file"` carried; everything dropped is reproduced in pi history or
regenerated by CC.

## Seam 4: System prompt — ✅ Clean

Bridge forwards pi's prompt as string → replaces CC's preset entirely. CC's
`buildSystemPromptBlocks` + cache_control work normally on it. No
double-injection.

## Seam 5: Feature flags — ⚠️ Fragile, not fixable

GrowthBook flags flip normalization mid-session → cache miss. This is the CC
baseline (~25%), not bridge damage. No correctness bugs regardless of flag state.

`tengu_anti_distill_fake_tool_injection` could inject unexpected content but
only fires for suspected distillation — not a bridge concern.
